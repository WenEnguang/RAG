# 项目路线图

本文件只记录项目状态、尚未完成的工作和验收条件。已完成实验的指标与结论见 [`RESULTS.md`](RESULTS.md)，完整过程见 [`../experiments/`](../experiments/)。

## 工作原则

- 先建立可运行基线和稳定评测，再做策略优化。
- 一次实验尽量只改变一个关键变量。
- 对照实验固定语料、测试集、模型、Prompt、温度和非目标参数。
- 指标变化必须结合成功案例、失败案例、延迟与成本解释。
- 未在固定评测条件下验证的能力，只能标为“已实现”或“待验证”，不能写成性能提升。

第一轮当前最佳组合是：**metadata 过滤 -> child 命中 -> parent 映射 -> 结构化生成**。这不是最终默认架构；它还需要在更大、更接近真实使用场景的评测集上验证质量、延迟和成本。

## 下一阶段优先级

### P0: 开源可复现性

目标：让外部读者能够在不依赖作者私有环境的前提下运行最小闭环。

- [ ] 解决 `scripts/TestsetGenerator.py` 中遗留的 Git 冲突标记。
- [ ] 在 `pyproject.toml` 或独立 requirements 文件中锁定已验证依赖版本。
- [ ] 提供脱敏 demo Markdown 数据、预期输出和最小测试集。
- [ ] 将 CPU/GPU 设备选择收敛至 `config/settings.py` 或自动探测逻辑。
- [ ] 统一 `evalute/evaluate`、`hybird/hybrid` 等命名。
- [ ] 为检索模式提供 CLI，例如 `--retriever vector|hybrid|parent-child|self-query-parent`。

验收：新环境按照 README 能完成环境检查、建立索引、运行一次查询和一次小规模评测；不需要访问私有笔记。

### P1: 评测集可信度与实验纪律

目标：让 20 条合成样本的早期发现能够接受更严格检验。

- [ ] 扩展到 80-150 条版本化评测样本。
- [ ] 引入人工黄金问题、域外拒答问题、错别字/模糊问法和多跳问题。
- [ ] 将测试集与知识库版本显式写入每份实验记录。
- [ ] 对同一配置重复运行，记录评测波动。
- [ ] 增加人工抽查，或使用不同于生成模型的评测模型以降低同源自评偏差。

验收：每个策略在完整评测集、关键子集和重复运行中的表现都可追溯；域外问题单独统计拒答质量。

### P2: 性能、成本与可观测性

目标：从“质量最好”推进到“质量、延迟与成本可权衡”。

- [ ] 记录检索延迟、端到端延迟、上下文长度、输入/输出 Token 和 API 成本。
- [ ] 统计 P50/P95 延迟与失败率。
- [ ] 比较 parent size、child size、child search k、top_k 对质量和成本的影响。
- [ ] 将结构化输出重试次数及解析失败纳入观测。

验收：每次评测能够输出质量指标与资源消耗；能够解释最佳质量方案是否值得作为默认方案。

### P3: 下一轮检索与文档结构优化

目标：在现有结论基础上探索更有信息增益的方向。

- [ ] 实现 Markdown 结构感知切分：标题层级、列表、表格和代码块完整性。
- [ ] 为 chunk 保留标题路径、文件名、文档类型和位置等 metadata。
- [ ] 接入 Rerank，在扩大候选集后选择最终上下文。
- [ ] 在更大、更高主题重叠的语料上复验 Hybrid 与 Multi-Query。
- [ ] 提升日期 metadata 的分辨率，验证时间过滤是否真实改变检索质量。
- [ ] 引入来源展示与引用文本定位，而不仅是上下文编号。

验收：每个新增模块先单独对照，再进入组合消融实验；结果中同时报告收益、回退案例和资源代价。

### P4: 文档范围扩展

目标：从纯 Markdown 笔记扩展到多格式个人知识库。

- [ ] 接入 PDF 解析，并保留文件名、页码和页内位置。
- [ ] 统一 Markdown/PDF 的 metadata 模型。
- [ ] 设计增量索引：新增、更新、删除笔记后只处理变化文档。

验收：回答可展示可靠来源定位；索引更新不会混入旧版数据。

## 组合策略与消融规则

当前已验证的组合包含 metadata 过滤、父子分块和结构化生成。继续加入 Rerank、查询改写或其他模块时，必须进行消融而非直接堆叠：

```text
baseline
-> parent-child
-> parent-child + structured
-> self-query + parent-child + structured
-> + one new module
```

每一步至少报告：四项 RAGAS 指标、引用统计、延迟/Token/成本、三个典型成功案例和三个典型失败案例。

## 评测集构成建议

| 来源 | 建议比例 | 作用 |
| --- | ---: | --- |
| RAGAS 合成问题 | 50-60% | 覆盖一般知识点和难度梯度 |
| 人工黄金问题 | 25-30% | 接近真实查询方式，提供可信参考答案 |
| 域外 / 对抗问题 | 10-15% | 评估拒答、幻觉与边界行为 |

域外问题应单独报告拒答准确性，不与正常问答的平均 RAGAS 分数混合。
