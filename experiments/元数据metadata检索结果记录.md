## 元数据metadata检索结果记录
首先说明，向量的计算只取决于page_content字段的内容，其他字段不会影响向量计算结果。
跟metadata里存放了什么内容都无关。为此，SelfQueryRetriever在检索时只会使用page_content字段的内容来计算向量，并且在检索结果中也只会返回page_content字段的内容。
- 第一步：语义检索：用户的问题照常转为向量，和向量库里的向量做相似度检索
- 第二步：元数据过滤：在检索结果中，使用metadata字段的内容进行过滤，筛选出符合条件的结果。

所以，因为之前的向量库中的父子分块索引并没有绑定上metadata字段，所以是需要重新建立索引，为此先删除之前的父子分块时建立的索引。
```python 
python scripts/check_index.py --list / --delete
```
然后，就是重新跑一遍父子分块索引的建立脚本，建立索引时绑定上metadata字段。
```python
python scripts/build_parent_child_index.py
```
此时建立的父子分块索引是带有metadata字段的，之后就可以使用SelfQueryRetriever来进行元数据检索了。

根据结果显示：
- `faithfulness`指标有明显的提升，通过"元数据过滤（排除无关主题）+父子分块（信息完整）+ 结构话引用（强制可核查）"的组合，可以很好地防止防幻觉效果。
- `context precison`指标也是有明显提升的，说明通过父子分块结构补充上下文后，LLM在做判断时更容易做出正确的引用编号选择。
- `context recall`指标没有达到最好的水平，元数据过滤本质上是在"排除"一部分候选内容，即使这次没有误伤到答题所需的关键信息，理论上"先过滤再检索"相比"直接在全量语料里检索"，天然会有极小概率漏掉一些边缘相关的内容。这个代价换来了大幅提升的Faithfulness和Precision，是一次很划算的权衡。
